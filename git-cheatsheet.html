工作区你正在编辑的文件夹

暂存区这次要提交的改动清单
→git commit
本地仓库你电脑上的存档历史

远程仓库GitHub 上的副本
区域是什么对应命令
工作区你正在编辑的文件夹改文件本身
暂存区待提交清单，决定这次包含哪些改动git add
本地仓库你电脑上的存档历史（.git 文件夹）git commit
远程仓库GitHub 上的副本git push
git add = 挑菜，决定这顿吃什么
git commit = 打包封存，贴标签存档
git push = 送货上门，同步到 GitHub
git pull = 取货，把远程更新拉回本地

为什么要分两步？因为一次提交可以只包含部分改动（比如"改脚本"和"补文档"分两次提交），历史才清晰，出问题也能精确回退。

2首次上传：完整流程

第 0 步：配置身份（每台电脑只做一次）
git config --global user.name "你的名字"
git config --global user.email "GitHub绑定的邮箱"

user.name 只是提交记录里的署名，中文也行；user.email 必须是 GitHub 账号绑定并验证过的邮箱，否则提交不会关联到你的账号（头像和贡献记录都不会显示）。

第 1 步：把文件夹变成仓库
cd 项目文件夹路径
git init
第 2 步（必做）：创建 .gitignore
__pycache__/
*.db
key.txt

具体该写什么，见第 4 节"安全线"。

第 3 步：提交第一个存档
git add .
git commit -m "说明这次做了什么"
第 4 步：在 GitHub 上建仓库

网页操作：右上角 + → New repository → 填名字 → 选 Public → 不要勾选 README / .gitignore / license（保持空仓库，避免和本地冲突）→ Create。

第 5 步：连接远程仓库
git remote add origin https://github.com/登录名/仓库名.git

origin 是给远程地址起的绰号，约定俗成。登录名是 github.com/xxx 里的 xxx，不是昵称（昵称可以有中文，登录名不行）。

第 6 步：统一分支名
git branch -M main

GitHub 默认叫 main，本地新建仓库默认叫 master，改成一致。-M 大写表示强制改名。

第 7 步：推送
git push -u origin main

-u 建立追踪关系，之后只需敲 git push。首次推送会弹浏览器要求授权，点同意即可。

第 8 步：验证

刷新 GitHub 页面看到文件；终端里 git status 显示 nothing to commit, working tree clean。

3日常三连与提交信息

git add .
git commit -m "这次改了什么"
git push

提交信息怎么写

  • 说清"做了什么"：添加sqlite3练习脚本 比 更新 有用一百倍
  • 一条提交只做一件事：改脚本和补文档分两次提交
  • 动词开头：添加 / 修正 / 删除 / 重构

每完成一段工作就提交一次。提交记录本身就是你的学习履历，面试时可以直接把仓库链接发过去。

4安全线：哪些文件绝对不能进仓库

类型例子为什么
密钥、密码key.txt、.env泄露等于别人拿你的账号花钱。而且即使之后删除，git 历史里依然能翻出来，只能作废重发
数据库文件*.db二进制文件，GitHub 无法预览内容；脚本能自动生成；每次运行都变动，制造噪音
缓存、编译产物__pycache__/机器自动生成，没有保留价值
一句话原则：能自动生成的、含密码的，都不进仓库。仓库里只放源码、文档、配置模板。

三道验证（缺一不可）

命令作用
git check-ignore -v 文件名查出是 .gitignore 里哪一条规则拦住了它
git status --ignored列出所有被忽略的文件（前面标 !!）
git ls-files列出仓库里所有已跟踪的文件——用它确认密钥确实不在其中

提交含密钥的代码后，正确做法是：立刻去平台重置密钥，再用上面的三道验证确认新密钥没有再进仓库。

5自查工具箱：常用查看命令

命令看什么
git status当前有哪些改动、哪些已暂存、是否与远程同步
git log --oneline提交历史，一行一条，看自己干过什么
git remote -v远程仓库地址，排查"推错地方"
git branch -vv分支列表和追踪关系，确认自己在哪个分支
git check-ignore -v 文件名文件为什么没进仓库
git ls-files仓库里到底有哪些文件被跟踪

6状态符号表（git status 常看）

符号含义
??未跟踪的新文件（git 还不认识它）
A已加入暂存区的新文件
M已修改的文件
D已删除的文件
!!被忽略的文件（不会进仓库）
无输出 / clean所有改动都已提交，干净
## main...origin/main本地和远程完全同步
## main...origin/main [ahead 1]有 1 个提交还没推上去，补一条 git push

8踩坑复盘（真实经历）

  1. 占位符必须替换：模板里写"你的登录名"，就不能原样粘贴，否则网址里会真的出现这五个中文字。
  2. 命令末尾的点不能丢：git add . 里的点代表"当前目录下所有改动"。
  3. 先 commit 再 push：顺序是 add → commit → push，跨过任何一步都会卡住。
  4. pull 和 push 方向相反：pull 把远程改动拉下来，push 才把本地提交送上去。
  5. 数据库文件"消失"：被 .gitignore 挡住了。这是它在正常工作——*.db 本来就不该进仓库。
  6. 提交前后各看一次 status：add 之后如果没看到期待的文件，先怀疑忽略规则。
  7. 报错信息会给答案：Maybe you wanted to say 'git add .'? 就是 git 自己把正确写法告诉你了。
