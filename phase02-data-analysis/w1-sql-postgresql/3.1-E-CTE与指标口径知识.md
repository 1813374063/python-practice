## 一、CTE（WITH）：给子查询起名字

CTE 全称 Common Table Expression，用 `WITH` 给一个子查询**起名字**，之后可以像表一样反复引用它。

### 语法骨架

```sql
WITH 名字 AS (
    子查询
)
SELECT ... FROM 名字 ...;
```

### 它解决什么问题

把"套了好几层的子查询"拆成**可读的一步步**。对比一下 C3 那种嵌套：

```sql
-- 不用 CTE：套娃，难读
HAVING COUNT(*) > (SELECT AVG(c) FROM (SELECT COUNT(*) AS c FROM tickets GROUP BY dept_id) sub)

-- 用 CTE：拆开，每一步都有名字
WITH dept_cnt AS (
    SELECT dept_id, COUNT(*) AS c FROM tickets GROUP BY dept_id
)
SELECT dept_id, c FROM dept_cnt
WHERE c > (SELECT AVG(c) FROM dept_cnt);
```

> 关键点：**CTE 不改变查询结果，只改变可读性**。它只是"给子查询起名字"，不是新语法，更不影响性能判断的依据。

### 多个 CTE 可以串起来

```sql
WITH a AS (...),
     b AS (...)
SELECT ... FROM a JOIN b ...;
```

## 二、指标口径：数据的"定义说明书"

### 什么是口径

同一个指标，**定义不同，算出来的数就不同**。例如：

- "接诊量"：是按**人次**算，还是按**就诊次数**算？一个人一次挂两个科算 1 还是 2？
- "工单量"：算**全部工单**，还是只算**已关闭**的？重复上报要不要去重？
- "处理时长"：按**自然日**还是**小时**？（date 类型只能算自然日，要小时得用 timestamp）

**口径就是把这些"到底怎么算"提前说清楚。**

### 三个必背口径概念

| 概念 | 说明 | 例子 |
|---|---|---|
| 闭开区间 | 时间过滤用 `>= 月初 AND < 下月初` | `created_at >= '2026-10-01' AND created_at < '2026-11-01'`，不漏 10-31 也不重复 |
| 量纲 | 指标的单位性质 | 工单量（件）、接诊量（人次）、金额（元）——不同量纲不能直接相加 |
| 分母 | "平均值/占比"除的是谁 | C3 里"平均工单数"的分母是"有工单科室"还是"全部科室" |

### 为什么面试和实际工作都看重口径

- 数据岗最值钱的能力不是写 SQL，而是**把模糊的业务问题翻译成明确的口径**。
- 你 5 年实施经验里，"客户需求 → 口径澄清 → 反馈研发"就是干这个的，只是没显式命名。

## 三、练习题 E1–E2

| 题号 | 题目 | 考点 |
|---|---|---|
| E1 | 用 `WITH`（CTE）拆解：算出各科室**月均接诊量**，列出 Top 3 | WITH + GROUP BY + ORDER BY + LIMIT |
| E2 | 口径讨论题（写文字）：同一个月的「工单量」和「接诊量」有没有可比性？如果要一张"科室运营总览"，每列的指标口径怎么定？ | 指标口径 / 业务判断 |

**通过标准**：
- E1 结果顺序是 门诊部 → 急诊科 → 检验科。
- E2 能说出："工单量是问题事件数（件），接诊量是服务人次（人次），量纲不同，不能相加比较；总览应按科室分列展示，各列各自定口径。"

## 四、参考答案

```sql
-- E1
WITH dept_monthly AS (
    SELECT dept_id, ROUND(AVG(patient_count)) AS avg_visits
    FROM visits
    GROUP BY dept_id
)
SELECT d.dept_name, dm.avg_visits
FROM dept_monthly dm
JOIN departments d ON d.dept_id = dm.dept_id
ORDER BY dm.avg_visits DESC
LIMIT 3;

-- 结果：门诊部 2213、急诊科 1795、检验科 1498

-- E2（文字题，参考要点）
-- 工单量 = 问题事件数（量纲：件），接诊量 = 服务人次（量纲：人次），
-- 两者量纲不同，不能直接相加或比较。
-- 「科室运营总览」应分列展示：接诊量、工单量、工单占比、P1 数、平均处理时长，
-- 每一列都单独写清口径（时间范围、去重规则、单位）。
```

## 五、名词汇总

| 名词 | 一句话解释 | 容易混淆点 |
|---|---|---|
| CTE（WITH） | 用 WITH 给子查询起名字，方便复用和拆解。 | 只是可读性工具，不改变结果。 |
| 子查询 | 嵌在另一查询里的查询。 | CTE 是"把子查询提出来起名"。 |
| 指标口径 | 一个指标的统一定义（单位、去重、时间范围）。 | 口径不定，同一指标能算出不同结果。 |
| 闭开区间 | 时间过滤 `>= 月初 AND < 下月初`。 | 避免漏掉/重复边界时刻的记录。 |
| 环比 | 与上一期比较的增长率。 | 用 LAG 取上期值再相除。 |
| 量纲 | 指标的单位和性质（件/人次/元）。 | 不同量纲不能直接相加比较。 |
| 分母 | "平均值/占比"除的是谁。 | 分母选错，结论就错。 |

---

## 六、一句总结

> **CTE 让复杂 SQL 好读，口径让数据结论可信。**
> 前者是"怎么写清楚"，后者是"算什么才算对"——数据分析岗面试，后者更值钱。
