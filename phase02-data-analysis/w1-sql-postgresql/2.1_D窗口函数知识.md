## 一、什么是窗口函数（最重要的一节）

窗口函数 = **在"每一行"上做计算，但不把行合并**。它的结果是"给每一行加一列"，而不是"把多行压成一行"。

### 和 GROUP BY 的核心区别

| | GROUP BY | 窗口函数 |
|---|---|---|
| 结果行数 | 变少（每组一行） | 不变（每行都保留） |
| 作用 | 把组内多行"聚合"成一个值 | 在每一行上算一个"相对值" | 

直观对比（tickets 共 35 行）：

```sql
-- GROUP BY：35 行 → 9 行（每科室一行）
SELECT dept_id, COUNT(*) AS cnt
FROM tickets
GROUP BY dept_id;

-- 窗口函数：仍是 35 行，每行多一列"该科室工单总数"
SELECT ticket_id, dept_id,
       COUNT(*) OVER (PARTITION BY dept_id) AS 该科室工单数
FROM tickets
ORDER BY ticket_id;
```

第一句你得到"每个科室有多少工单"；第二句你得到"每张工单 + 它所属科室一共有多少工单"。

> 一句话记牢：**GROUP BY 在"压缩行"，窗口函数在"给每行贴标签"。**

## 二、语法骨架

```sql
函数名() OVER (
    PARTITION BY 分组列      -- 按什么"分组"（可不写）
    ORDER BY 排序列          -- 组内按什么"排序"（可不写）
)
```

- `PARTITION BY`：把行切成一个个"窗口"（类似 GROUP BY 的分组，但**不合并行**）。
- `ORDER BY`：决定窗口内行的先后顺序——影响 `ROW_NUMBER` 的编号、`LAG` 取"上一行"、`SUM` 的"累计顺序"。

## 三、四个必会函数

### 1. ROW_NUMBER()：编号

给组内每行分配**唯一连续**编号 1,2,3…（哪怕并列，也强行给不同号）。

```sql
SELECT dept_id, ticket_id, created_at,
       ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY created_at) AS rn
FROM tickets;
```

### 2. RANK() vs DENSE_RANK()：排名

| 函数 | 并列时 | 名次 |
|---|---|---|
| RANK | 同名次，**跳号** | 1,1,3,3,3,6… |
| DENSE_RANK | 同名次，**不跳号** | 1,1,2,2,2,3… |
| ROW_NUMBER | 不并列，硬编号 | 1,2,3,4,5,6… |

当前数据工单量：内科 6、检验科 6、外科 5、门诊 5、急诊 5、儿科 3、药房 3、放射 1、护理 1。
`RANK` 结果是 **1,1,3,3,3,6,6,8,8**；`DENSE_RANK` 是 **1,1,2,2,2,3,3,4,4**。

### 3. LAG(列) / LEAD(列)：取上/下一行

`LAG(列)` 取当前行**前面**一行的值，`LEAD(列)` 取**后面**一行的值。最常见用途：算环比（本月 vs 上月）。

### 4. SUM(列) OVER (...)：累计

- 带 `ORDER BY`：按顺序**逐行累计**（跑步计分）。
- 不带 `ORDER BY`：整个分区求**总和**（每行都是同一个总数）。

## 四、练习题 D1–D4

| 题号 | 题目 | 考点 |
|---|---|---|
| D1 | 给每个科室的工单按创建时间从早到晚编号（每科内部 1,2,3…） | ROW_NUMBER + PARTITION BY |
| D2 | 各科室按工单量排名（并列同名次、跳号） | RANK |
| D3 | 内科每个月的接诊量，以及环比增长率（%） | LAG |
| D4 | 每个科室接诊量的累计值（按时间累积） | SUM OVER + PARTITION BY |

**通过标准**：
- D2 结果里排名是 1,1,3,3,3,6,6,8,8（RANK 跳号）；能说清 RANK 和 ROW_NUMBER 的区别。
- D3 里内科 10→11 月环比约 **−25.4%**。
- D4 内科累计到 11 月 = **4510**。

## 五、参考答案

```sql
-- D1
SELECT dept_id, ticket_id, created_at,
       ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY created_at) AS rn
FROM tickets
ORDER BY dept_id, rn;

-- D2
SELECT dept_id, COUNT(*) AS cnt,
       RANK() OVER (ORDER BY COUNT(*) DESC) AS rk
FROM tickets
GROUP BY dept_id
ORDER BY dept_id;

-- D3（环比增长率 = (本月 - 上月) / 上月 × 100）
SELECT visit_month, patient_count,
       LAG(patient_count) OVER (ORDER BY visit_month) AS prev_count,
       ROUND(
         (patient_count - LAG(patient_count) OVER (ORDER BY visit_month))::numeric
         / LAG(patient_count) OVER (ORDER BY visit_month) * 100, 2
       ) AS pct_change
FROM visits
WHERE dept_id = 1
ORDER BY visit_month;

-- D4（累计：加 ORDER BY 才逐行累加）
SELECT dept_id, visit_month, patient_count,
       SUM(patient_count) OVER (PARTITION BY dept_id ORDER BY visit_month) AS running_total
FROM visits
ORDER BY dept_id, visit_month;
```

## 六、名词汇总

| 名词 | 一句话解释 | 容易混淆点 |
|---|---|---|
| 窗口函数 | 在每一行上计算、但不合并行的函数。 | 与 GROUP BY 相反：它保留所有行。 |
| OVER | 定义窗口函数的分组和排序。 | OVER 里 PARTITION BY / ORDER BY 都可省略。 |
| PARTITION BY | 把行切成窗口（分组）。 | 只影响计算范围，不减少行数。 |
| ROW_NUMBER | 给每行唯一连续编号。 | 并列时也会给不同编号。 |
| RANK | 排名，并列同名次且跳号。 | 1,1,3,3,3,6 是 RANK。 |
| DENSE_RANK | 排名，并列同名次不跳号。 | 1,1,2,2,2,3 是 DENSE_RANK。 |
| LAG / LEAD | 取当前行之前/之后某行的值。 | 常用于环比（LAG）和同比。 |
| 累计值 | 窗口内按顺序逐行相加。 | 加 ORDER BY 才累计，不加是分区总和。 |

---

## 七、最需要区分的三句话

```text
窗口函数"贴标签"，GROUP BY"压缩行"
RANK 跳号，DENSE_RANK 不跳号，ROW_NUMBER 不并列
LAG 看上一行（环比），SUM + ORDER BY 是累计
```
