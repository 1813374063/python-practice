# Part D 窗口函数 —— 一周练习（每天 8 题）

> 数据：`hospital_practice` 库（departments 9 / engineers 4 / tickets 35 / visits 32），在 DBeaver 里跑。
> 用法：每天一个主题，**先自己写 → 跑 → 对照文末该天的参考答案**。
> 每题标注【考点】和【预期】，预期帮你自查结果对不对。

## Day 1｜ROW_NUMBER 编号

**目标**：掌握 `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)`，理解"给每行贴一个顺序号"。

| # | 题目 | 考点 |
|---|---|---|
| 1.1 | 给 tickets 每行一个全局行号，按 ticket_id 升序 | ROW_NUMBER + ORDER BY（无分区） |
| 1.2 | 给每个科室的工单按创建时间从早到晚编号（每科内部 1,2,3…） | PARTITION BY 分区 |
| 1.3 | 同上，但按创建时间**倒序**编号（每科最新的工单是 1） | ORDER BY DESC |
| 1.4 | 给每个工程师处理的工单编号（按工程师分组，按时间排序） | 换一个分区列 |
| 1.5 | 找出每个科室**最早**的那张工单（编号=1 的） | ROW_NUMBER=1 + 子查询 |
| 1.6 | 找出每个工程师**最新**处理的那张工单 | ROW_NUMBER=1（倒序） |
| 1.7 | 按优先级分组给工单编号（P1 内 1,2,3…，P2 内 1,2,3…） | 按 category/priority 分区 |
| 1.8 | 每科室按时间编号后，只保留每科**最早的 2 条**工单 | ROW_NUMBER + WHERE rn<=2 |

**预期自查**：1.1 共 35 行、编号 1–35；1.2 内科编号 1–6；1.5 每科各 1 行（共 9 行）；1.8 每科最多 2 行。

## Day 2｜RANK / DENSE_RANK 排名

**目标**：搞清 RANK（跳号）和 DENSE_RANK（不跳号）的区别。

| # | 题目 | 考点 |
|---|---|---|
| 2.1 | 各科室按工单量排名（RANK，降序） | RANK 基础 |
| 2.2 | 各科室按工单量排名（DENSE_RANK，降序），和 2.1 对比名次 | 跳号 vs 不跳号 |
| 2.3 | 各工程师按处理工单量排名 | 换数据源 |
| 2.4 | 各优先级（P1/P2/P3）按工单量排名 | 分组后排名 |
| 2.5 | 各科室按 **11 月接诊量**排名 | 从 visits 取数 |
| 2.6 | 找出工单量排名**第 1** 的科室（RANK=1，注意并列） | RANK=1 |
| 2.7 | 找出工单量排名**第 2** 的科室（观察：并列第一时有没有"第 2 名"） | 理解跳号 |
| 2.8 | 工单量排**前三名**的科室（用 DENSE_RANK<=3） | DENSE_RANK 应用 |

**预期自查**：2.1 名次是 1,1,3,3,3,6,6,8,8；2.2 是 1,1,2,2,2,3,3,4,4；2.6 返回内科+检验科两行；2.7 结果为空（因为两个并列第一，直接跳到第 3 名）。

## Day 3｜LAG / LEAD 前后行

**目标**：会取"上一行/下一行"，用于环比、差值、前后对比。

| # | 题目 | 考点 |
|---|---|---|
| 3.1 | 内科每月接诊量，以及**上月**接诊量（LAG） | LAG 基础 |
| 3.2 | 内科每月接诊量的**环比增长率**（%）= (本月−上月)/上月×100 | LAG + 计算 |
| 3.3 | **各科室**每月接诊量 + 环比增长率（按科室分区） | LAG + PARTITION BY |
| 3.4 | 内科每月接诊量，以及**下月**接诊量（LEAD） | LEAD |
| 3.5 | 内科接诊量，以及"两个月前"的接诊量（LAG 偏移 2 行） | LAG(列, 偏移量) |
| 3.6 | 内科接诊量，以及"本月 − 上月"的**差值** | LAG 做差 |
| 3.7 | 找出各科室**环比下降**的月份（本月 < 上月） | LAG + 过滤 |
| 3.8 | 工单表：每张工单，以及**同科室上一张工单**的创建时间 | LAG 在 tickets 上 |

**预期自查**：3.2 内科环比为 +4.17% → −5.6% → −25.42%；3.3 每科第一行环比是 NULL；3.7 内科 10 月、11 月各出现一次。

## Day 4｜聚合窗口 SUM / AVG / COUNT OVER

**目标**：理解"窗口聚合"——累计、移动平均、占比、分组总数。

| # | 题目 | 考点 |
|---|---|---|
| 4.1 | 每张工单，以及**该科室的工单总数**（每行都显示） | COUNT OVER |
| 4.2 | 内科每月接诊量的**累计值**（逐月累加） | SUM OVER + ORDER BY |
| 4.3 | **各科室**每月接诊量的累计值（按科室分区累计） | SUM + PARTITION BY |
| 4.4 | 各科室每月接诊量，以及**该科室的平均接诊量**（每行都显示） | AVG OVER |
| 4.5 | 各科室每月接诊量，以及**该月占该科室四个月总接诊量的占比**（%） | SUM OVER 算占比 |
| 4.6 | 各科室每月接诊量的 **3 个月移动平均**（本月+前两个月） | ROWS BETWEEN 2 PRECEDING |
| 4.7 | 每张工单，以及**该科室已解决工单的累计数**（按时间累计） | 条件累计（较难） |
| 4.8 | 各科室每月接诊量，以及**该科室截至本月的历史最大值** | MAX OVER + ORDER BY |

**预期自查**：4.2 内科累计 = 1200, 2450, 3630, 4510；4.4 内科每行都是 1127.5；4.6 内科 11 月移动平均 ≈1103。

## Day 5｜TopN 与综合

**目标**：把窗口函数和子查询/过滤结合，解决"取每组前 N 名"。

| 5.3 | 每科室**工单量最高**的科室工单量是多少（并列都列出） | RANK=1 |
| 5.4 | 每科室工单量，以及"比它工单**多**的科室有几个"（名次−1） | RANK 变体 |
| 5.5 | 每科室按时间编号，只取每科**第 2 张**工单 | ROW_NUMBER=2 |

**预期自查**：5.2 每科一行（8 行）；5.5 放射科、护理部没有第 2 张（不会出现）；5.8 内科、检验科差值为 0。

## Day 6｜进阶：NTILE / FIRST_VALUE / LAST_VALUE

**目标**：掌握分桶、取首尾值，以及 LAST_VALUE 的经典"坑"。

| # | 题目 | 考点 |
|---|---|---|
| 6.1 | 把 9 个科室按工单量**均分成 3 档**（NTILE(3)） | NTILE |
| 6.2 | 把 35 张工单按创建时间均分成 4 组，标组号 | NTILE(4) |
| 6.3 | 每张工单 + 该科室**最早工单**的创建时间（FIRST_VALUE） | FIRST_VALUE |
| 6.4 | 每张工单 + 该科室**最新工单**的创建时间（LAST_VALUE，注意坑） | LAST_VALUE + 全窗口帧 |
| 6.5 | 各科室每月接诊量 + 该科室**第一个月**接诊量 | FIRST_VALUE |
| 6.6 | 各科室工单量，以及**全局工单量最多的科室**的工单量（对照 5.8） | MAX OVER 无分区 |
| 6.7 | 各科室工单量占比（该科室/全局总数，百分比） | SUM OVER 无分区 |
| 6.8 | 各科室接诊量最高月份的接诊量（FIRST_VALUE + 子查询组合） | FIRST_VALUE 综合 |

**预期自查**：6.1 前 3 名（内科、检验科、外科）在第 1 档；6.6 每行都是 6（全局最大值）；6.7 内科占比 ≈ 6/35 ≈ 17.14%。

## Day 7｜综合实战与易错点

```sql
SELECT dept_id, cnt, rk, rk - 1 AS more_than_me FROM (

         RANK() OVER (ORDER BY COUNT(*) DESC) AS rk
  FROM tickets GROUP BY dept_id
) t ORDER BY rk;

-- 5.5
SELECT dept_id, ticket_id, created_at FROM (
  SELECT dept_id, ticket_id, created_at,
         ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY created_at) AS rn
  FROM tickets
) t WHERE rn = 2 ORDER BY dept_id;

-- 5.6（环比最高的一条）
SELECT * FROM (
  SELECT dept_id, visit_month, patient_count,
         ROUND((patient_count - LAG(patient_count) OVER (PARTITION BY dept_id ORDER BY visit_month))::numeric
               / LAG(patient_count) OVER (PARTITION BY dept_id ORDER BY visit_month) * 100, 2) AS pct
  FROM visits
) t ORDER BY pct DESC NULLS LAST LIMIT 1;

-- 5.7（窗口 + 聚合混用：先 GROUP BY 再窗口，最早工单用子查询）
WITH dept_cnt AS (
  SELECT dept_id, COUNT(*) AS cnt FROM tickets GROUP BY dept_id
), dept_first AS (
  SELECT dept_id, MIN(created_at) AS first_date FROM tickets GROUP BY dept_id
)
SELECT dc.dept_id, dc.cnt,
       RANK() OVER (ORDER BY dc.cnt DESC) AS rk,
       df.first_date
FROM dept_cnt dc JOIN dept_first df ON df.dept_id = dc.dept_id
ORDER BY dc.dept_id;

-- 5.8（与第一名的差距）
SELECT dept_id, COUNT(*) AS cnt,
       MAX(COUNT(*)) OVER () - COUNT(*) AS gap_to_top
FROM tickets GROUP BY dept_id ORDER BY dept_id;
```

### Day 7 答案

```sql
-- 7.1
SELECT dept_id, COUNT(*) AS cnt,
       RANK() OVER (ORDER BY COUNT(*) DESC) AS rk,
       DENSE_RANK() OVER (ORDER BY COUNT(*) DESC) AS drk
FROM tickets GROUP BY dept_id ORDER BY dept_id;

-- 7.2（11 月 vs 10 月环比，降序）
WITH nov AS (SELECT dept_id, patient_count AS c FROM visits WHERE visit_month='2026-11-01'),
     oct AS (SELECT dept_id, patient_count AS c FROM visits WHERE visit_month='2026-10-01')
SELECT n.dept_id, n.c, o.c AS prev_c,
       ROUND((n.c - o.c)::numeric / o.c * 100, 2) AS pct
FROM nov n JOIN oct o ON o.dept_id = n.dept_id
ORDER BY pct DESC;

-- 7.3（连续两个月下降：本月<上月 且 上月<上上月）
SELECT dept_id, visit_month, patient_count FROM (
  SELECT dept_id, visit_month, patient_count,
         LAG(patient_count) OVER (PARTITION BY dept_id ORDER BY visit_month) AS p1,
         LAG(patient_count, 2) OVER (PARTITION BY dept_id ORDER BY visit_month) AS p2
  FROM visits
) t WHERE patient_count < p1 AND p1 < p2
ORDER BY dept_id, visit_month;

-- 7.4（每科第 1 张与第 2 张工单的时间差）
WITH ranked AS (
  SELECT dept_id, created_at,
         ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY created_at) AS rn
  FROM tickets
), first_two AS (
  SELECT dept_id,
         MAX(created_at) FILTER (WHERE rn=1) AS d1,
         MAX(created_at) FILTER (WHERE rn=2) AS d2
  FROM ranked GROUP BY dept_id
)
SELECT dept_id, d1, d2, d2 - d1 AS gap_days
FROM first_two ORDER BY dept_id;

-- 7.5（高于/不高于全局平均）
SELECT dept_id, cnt,
       AVG(cnt) OVER () AS global_avg,
       CASE WHEN cnt > AVG(cnt) OVER () THEN '高于平均' ELSE '不高于平均' END AS flag
FROM (SELECT dept_id, COUNT(*) AS cnt FROM tickets GROUP BY dept_id) t
ORDER BY dept_id;

-- 7.6
SELECT engineer_id, COUNT(*) AS cnt,
       RANK() OVER (ORDER BY COUNT(*) DESC) AS rk
FROM tickets GROUP BY engineer_id;

-- 7.7（移动平均 + 差值）
SELECT dept_id, visit_month, patient_count,
       ROUND(AVG(patient_count) OVER (PARTITION BY dept_id ORDER BY visit_month
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)) AS moving_avg,
       patient_count - ROUND(AVG(patient_count) OVER (PARTITION BY dept_id ORDER BY visit_month
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)) AS diff
FROM visits ORDER BY dept_id, visit_month;

-- 7.8（综合大题）
WITH t_cnt AS (
  SELECT dept_id, COUNT(*) AS ticket_cnt FROM tickets GROUP BY dept_id
),
v_sum AS (
  SELECT dept_id, SUM(patient_count) AS visit_total FROM visits GROUP BY dept_id
),
t_first AS (
  SELECT dept_id, MIN(created_at) AS first_date FROM tickets GROUP BY dept_id
)
SELECT tc.dept_id, tc.ticket_cnt,
       RANK() OVER (ORDER BY tc.ticket_cnt DESC) AS ticket_rk,
       vs.visit_total,
       RANK() OVER (ORDER BY vs.visit_total DESC) AS visit_rk,
       tf.first_date
FROM t_cnt tc
LEFT JOIN v_sum vs ON vs.dept_id = tc.dept_id
LEFT JOIN t_first tf ON tf.dept_id = tc.dept_id
ORDER BY tc.dept_id;
```

## 易错点清单（做完对照）

1. **RANK 跳号，DENSE_RANK 不跳号，ROW_NUMBER 不并列**——7.1 一题看清三者。
2. **LAG 的第一行是 NULL**——因为前面没有行，环比第一行永远是 NULL。
3. **累计必须加 ORDER BY**——`SUM(...) OVER (PARTITION BY ...)` 不加 ORDER BY 是"分区总和"（每行相同），加了才是"逐行累计"。
4. **LAST_VALUE 的坑**——默认窗口帧只到"当前行"，所以 LAST_VALUE 默认拿到的是当前行；要拿真正的"最后一行"必须写 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`。
5. **窗口函数不能直接放 WHERE**——`WHERE ROW_NUMBER() ... = 1` 会报错，必须套一层子查询，再在外层过滤。
6. **占比的分母要无分区**——算"该科室占全局"时，`SUM(...) OVER ()`（不带 PARTITION BY）才是全局总量。
