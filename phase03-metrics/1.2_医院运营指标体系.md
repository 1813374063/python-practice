# 医院运营指标体系

> 文档性质：数据实施 / 数据分析岗位作品集项目
> 数据源：练习库 `hospital_practice`（departments 9 / engineers 4 / tickets 35 / visits 32）
> 时间范围：2026-08 ～ 2026-11
> 编制日期：2026-11-26

---

## 一、文档说明

本文件定义医院信息科视角下的运营指标体系，共 **15 个可计算指标**，每个指标都写明：

- **口径**：分子 / 分母 / 去重规则 / 时间归属 / 数据源
- **取数 SQL**：可直接在 `hospital_practice` 库执行
- **当前值**：用练习库真实算出的结果

**核心原则**：报数必须带口径。同一个指标在不同口径下可能差 20+ 个百分点（见指标 9/10 的解决率）。

## 三、逐指标口径与取数 SQL

### 指标 1：门诊接诊总量

```text
分类：运营量级
口径：
  分子：visits.patient_count 求和
  分母：无
  去重：按 dept_id + visit_month 唯一（表中已是月度汇总，无需再汇总）
  时间：按 visit_month 归属
  数据源：visits
当前值：40810
```

```sql
SELECT SUM(patient_count) AS 总接诊量 FROM visits;
```

---

### 指标 2：月度门诊接诊量

```text
分类：运营量级
口径：
  分子：按月分组的 patient_count 求和
  分母：无
  去重：dept_id + visit_month
  时间：visit_month
  数据源：visits
当前值：8月10140 / 9月10330 / 10月10480 / 11月9860
```

```sql
SELECT visit_month, SUM(patient_count) AS 月度接诊量
FROM visits
GROUP BY visit_month
ORDER BY visit_month;
```

---

### 指标 3：各科接诊量占比

```text
分类：结构
口径：
  分子：某科 4 个月 patient_count 之和
  分母：全院 4 个月 patient_count 之和（40810）
  去重：dept_id + visit_month
  时间：2026-08 ~ 2026-11
  数据源：visits JOIN departments
当前值：门诊部21.69% / 急诊科17.59% / 检验科14.68% / 内科11.05% / 放射科11.03% / 外科9.78% / 儿科8.14% / 药房6.05%
```

```sql
SELECT d.dept_name,
       SUM(v.patient_count) AS 接诊量,
       ROUND(SUM(v.patient_count) * 100.0
             / (SELECT SUM(patient_count) FROM visits), 2) AS 占比
FROM visits v
JOIN departments d ON d.dept_id = v.dept_id
GROUP BY d.dept_name
ORDER BY 接诊量 DESC;
```

---

### 指标 4：门诊量环比

```text
分类：增长
口径：
  分子：本月总量 − 上月总量
  分母：上月总量
  去重：visit_month
  时间：本月 / 上月
  数据源：visits
当前值：-5.92%（11月 9860 vs 10月 10480）
```

```sql
SELECT
  ROUND(
    (SUM(CASE WHEN visit_month = '2026-11-01' THEN patient_count ELSE 0 END)
     - SUM(CASE WHEN visit_month = '2026-10-01' THEN patient_count ELSE 0 END)) * 100.0
    / SUM(CASE WHEN visit_month = '2026-10-01' THEN patient_count ELSE 0 END), 2) AS 环比百分比
FROM visits;
```

---

### 指标 5：各科接诊环比贡献

```text
分类：增长 / 归因
口径：
  分子：某科 11 月接诊量 − 某科 10 月接诊量
  分母：无（贡献度 = 该科变化 / 总变化）
  去重：dept_id
  时间：2026-10 / 2026-11
  数据源：visits JOIN departments
当前值：内科-300 / 门诊部-150 / 急诊科-70 / 儿科-50 / 外科-30 / 检验科-30 / 放射科-20 / 药房+30
```

```sql
SELECT d.dept_name,
       SUM(CASE WHEN v.visit_month = '2026-10-01' THEN v.patient_count ELSE 0 END) AS 十月,
       SUM(CASE WHEN v.visit_month = '2026-11-01' THEN v.patient_count ELSE 0 END) AS 十一月,
       SUM(CASE WHEN v.visit_month = '2026-11-01' THEN v.patient_count ELSE 0 END)
       - SUM(CASE WHEN v.visit_month = '2026-10-01' THEN v.patient_count ELSE 0 END) AS 变化
FROM visits v
JOIN departments d ON d.dept_id = v.dept_id
WHERE v.visit_month IN ('2026-10-01','2026-11-01')
GROUP BY d.dept_name
ORDER BY 变化;
```

### 指标 7：月度工单量

```text
分类：运营量级
口径：
  分子：按 created_at 月份分组的 COUNT(*)
  分母：无
  去重：ticket_id
  时间：created_at（不是 resolved_at）
  数据源：tickets
当前值：9月11 / 10月13 / 11月11
```

```sql
SELECT to_char(created_at, 'YYYY-MM') AS 月份, COUNT(*) AS 工单量
FROM tickets
GROUP BY 1
ORDER BY 1;
```

### 指标 9：工单解决率（口径 A）

```text
分类：效率
口径：
  分子：status = 'resolved' 的工单数
  分母：全部工单数
  去重：ticket_id
  时间：全部
  数据源：tickets
当前值：48.57%
```

```sql
SELECT ROUND(COUNT(*) FILTER (WHERE status = 'resolved') * 100.0 / COUNT(*), 2) AS 解决率A
FROM tickets;
```

---

### 指标 10：工单解决率（口径 B）

```text
分类：效率
口径：
  分子：status IN ('resolved','closed') 的工单数
  分母：全部工单数
  去重：ticket_id
  时间：全部
  数据源：tickets
当前值：71.43%
```

```sql
SELECT ROUND(COUNT(*) FILTER (WHERE status IN ('resolved','closed')) * 100.0 / COUNT(*), 2) AS 解决率B
FROM tickets;
```

> **口径提示**：A 与 B 相差 22.86 个百分点。报表中必须写明用的是哪一口径，否则无法对账。

### 指标 12：工单平均处理时长

```text
分类：效率
口径：
  分子：SUM(resolved_at − created_at)，仅 resolved_at 非空的工单
  分母：resolved_at 非空的工单数（25 条）
  去重：ticket_id
  时间：按 resolved_at 归属
  数据源：tickets
当前值：0.44 天（总 11 天 / 25 条）
```

```sql
SELECT ROUND(AVG(resolved_at - created_at), 2) AS 平均处理天数
FROM tickets
WHERE resolved_at IS NOT NULL;
```

> 若只算 `status='resolved'`（17 条），平均为 0.06 天——同样是「平均处理时长」，口径不同结果差 7 倍。

### 指标 13：工程师工单负载

```text
分类：效率
口径：
  分子：按 engineer_id 分组的 COUNT(ticket_id)
  分母：无
  去重：ticket_id
  时间：全部
  数据源：engineers LEFT JOIN tickets
当前值：张伟(高级)12 / 李娜(中级)12 / 王强(初级)11 / 赵敏(初级)0
```

```sql
SELECT e.name, e.level, COUNT(t.ticket_id) AS 工单数
FROM engineers e
LEFT JOIN tickets t ON t.engineer_id = e.engineer_id
GROUP BY e.name, e.level
ORDER BY 工单数 DESC;
```

## 四、分析方法示例（完整报告）

以「2026 年 11 月门诊量环比下降」为例，按金字塔结构：

```text
结论：
11 月门诊量 9860 人次，环比 10 月（10480）下降 5.92%（-620 人次），
主因是内科（-300，约占总降幅 48%），其次是门诊部（-150）。

数据支撑：
1. 总量：10月 10480 → 11月 9860，环比 -620（-5.92%）
2. 加法拆解（按科室）：
   内科 -300、门诊部 -150、急诊科 -70、儿科 -50、
   外科 -30、检验科 -30、放射科 -20、药房 +30
3. 结构：门诊部占全院接诊量 21.69%，是第一大科室；
   内科占 11.05%，但其降幅贡献却接近一半。

建议：
1. 核查内科 11 月排班、停诊、系统故障记录，确认 -300 是否异常；
2. 对比 2025 年 11 月数据，判断是否季节性（当前库缺去年同期数据）；
3. 门诊部作为最大科室，同步排查 -150 的原因；
4. 药房是唯一正增长（+30），可进一步看是否为药品配送/取药流程优化。
```

## 五、维度与拆解方法

| 方法 | 本库示例 |
|---|---|
| 加法拆解 | 门诊量 = 各科室之和；工单量 = 各科室之和 |
| 乘法拆解 | 收入 = 人次 × 次均费用（本库缺费用数据，示意） |
| 漏斗拆解 | 工单：新建 → 受理 → 处理中 → 解决 → 关闭 |
| 对比 | 环比（11月 vs 10月）、科室横向对比、口径 A/B 对比 |
| 归因 | 各科环比贡献（指标 5），定位主要拖累项 |

## 六、暂不可算的指标（需补数据）

| 指标 | 缺什么 | 补齐方式 |
|---|---|---|
| 门诊量同比 | 2025 年同期数据 | 导入 2025-11 的 visits |
| 门诊收入 | 收费 / 收入表 | 新增 `revenue` 表 |
| 次均费用 | 收入 + 人次 | 收入 / 接诊量 |
| 超时工单数 | 超时阈值定义 | 先定口径（如 >3 天），再 `resolved_at - created_at > 3` |
| 系统可用率 | 监控日志 | 接入运维监控数据 |

> 诚实标注「暂不可算」比硬凑数字更重要——面试官问「你这个同比怎么来的」时，能说清缺什么、怎么补，比报了假数强。
