## 专业名词汇总

### 1. 第一次接口调用

| 名词 | 一句话解释 | 容易混淆点 |
|---|---|---|
| 大语言模型 | 根据输入上下文生成文本的模型。 | 模型不是数据库，不会自动知道最新院内文件。 |
| API | 程序之间按照约定交换请求和响应的接口。 | 调用 API 不等于训练模型。 |
| API Key | 调用接口时证明调用者身份的密钥。 | 密钥不能提交到 GitHub。 |
| `base_url` | 接口服务的统一地址。 | 地址和具体接口路径不是一回事。 |
| `model` | 指定本次使用哪个模型。 | 模型名必须与平台支持的名称一致。 |
| SDK | 方便程序调用接口的软件开发工具包。 | SDK 最终仍会发送 HTTP 请求。 |
| 请求 Request | 程序发送给模型服务的参数和消息。 | 本地变量只有进入请求后模型才能看到。 |
| 响应 Response | 模型服务返回的回答和统计信息。 | 响应包含的不只是回答正文。 |
| `messages` | 承载系统规则、用户输入和模型回答的消息列表。 | 参数名不能随意改写。 |
| `role` | 标明消息由谁产生。 | 常见值为 `system`、`user`、`assistant`。 |
| `user` | 用户输入对应的消息角色。 | 用户角色不是程序调用者身份认证。 |
| `assistant` | 模型生成内容对应的消息角色。 | 示例也可以由程序预先放入 assistant 消息。 |
| `content` | 消息或者响应中的可见文本。 | 生成统计里的 token 不等于 content。 |
| Token | 模型处理文本时使用的基本计量单位。 | 中文一个字不一定等于一个 token。 |
