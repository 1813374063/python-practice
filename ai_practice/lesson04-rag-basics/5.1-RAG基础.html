第 4 课 · RAG 基础

检索增强生成（RAG）

从外部资料检索到可校验回答的完整最小流程

1为什么需要 RAG

模型参数保存训练阶段的知识，但无法自动知道医院刚发布的最新制度。RAG 在每次回答前检索外部资料，再把资料放入当前提示词。 
参数记忆：固定在模型版本中的知识
非参数记忆：外部文档和数据库中的资料

RAG = Retrieval + Augmented + Generation
    = 检索     + 增强      + 生成

2最小数据流

知识资料
→ 按章节切分
→ 提取问题关键词
→ 给资料评分和排序
→ 选择前几名
→ 组装 system 和 user 消息
→ 模型生成回答
→ 校验字段和引用来源
RAG 不会修改模型参数，也不能保证答案一定正确。检索资料错误时，回答仍可能错误。

3资料准备

长制度不能整篇直接发送，需要按章节或语义边界切分成片段。

策略结果
按章节切分保留完整制度含义
固定字数切分可能切断句子或流程
片段太小缺少上下文
片段太大混入无关内容，增加 token

片段应保存 chunk_id、标题、正文、版本和访问级别。当前虚构制度被切成 5 个片段。

4关键词检索

当前最小实现使用关键词匹配：

标题命中 × 4
正文命中 × 1
按总分降序排列
默认取前 3 名
问题第一名资料分数
病历保存接口超时KB-00224
门诊叫号大屏黑屏KB-00121
新护士无法登录和查看排班KB-0033
药房无法打印处方KB-00413
门诊日报汇总不一致KB-00712
分数不是概率或准确率。共同词会造成误召回，例如“门诊日报”错误召回“门诊叫号大屏”。

5Grounded Prompt

检索资料通过 messages 交给模型：

system：只能根据资料回答
        不得编造院内制度
        必须保留资料编号
        资料不足必须明确说明

user：  [KB-007] 资料标题
        资料正文

        当前用户问题
最终回答格式包含 answer、used_sources、insufficient 和 need_human_review。

7程序校验与人工复核

层次检查内容
JSON 校验字段是否存在
引用校验used_sources 是否来自实际召回
业务复核资料是否真正支持回答，结论是否完整
JSON 格式正确不等于业务回答正确。引用编号存在也不等于资料一定相关。

8自查清单

  • 能区分模型参数记忆和外部资料。
  • 能说明 RAG 为什么不会修改模型参数。
  • 知道为什么要按章节切分。
  • 知道检索分数不是准确率。
  • 知道检索资料如何进入 messages。
  • 知道程序校验和人工复核的区别。
