# 第 4 课 RAG 专业名词词卡

本节按第 4 课的学习部分汇总专业名词。它不是完整 AI 词典，后续课程的名词会分别收录到各自课程的知识汇总文件中。

## 1. 资料准备

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| RAG | Retrieval-Augmented Generation，先检索外部资料，再让模型基于资料生成回答。 | 本课总主题，解决模型无法自动获得医院最新制度的问题。 | RAG 不重新训练模型，也不会自动保证回答正确。 |
| 参数记忆 | 模型训练后保存在参数中的知识。 | 用来解释模型为什么知道通用知识，却不知道最新院内制度。 | 它不是永久不变，模型升级或更换后参数知识会变化。 |
| 非参数记忆 | 模型参数之外，通过文档或数据库保存并在运行时检索的资料。 | 医院制度库和 FAQ 属于这类资料。 | 它不是模型自己学会的，而是程序在提问时查出来并放入提示词。 |
| 知识库 | 为检索准备的外部资料集合。 | 当前使用 `1.1-rag_knowledge.json` 模拟医院知识库。 | 知识库中的资料可能过时、错误或缺少权限控制，需要治理。 |
| 文档切分 | 把长文档拆成较小、可检索的片段。 | 避免整篇制度进入提示词，并提高定位精度。 | 切分不是越短越好，片段太小会丢失上下文。 |
| chunk | 文档切分后得到的资料片段。 | 检索实际返回和评分的基本单位。 | chunk 是资料片段，不是模型回答。 |
| `chunk_id` | 每个资料片段的唯一标识。 | 回答引用资料时用于标明来源。 | 编号本身不能证明资料内容一定相关。 |
| 元数据 | 描述资料片段的信息，例如标题、版本、权限和来源。 | 支持来源引用、权限控制、版本管理和过滤。 | 元数据不是资料正文，但对生产系统非常重要。 |
| `access_level` | 资料的访问级别。 | 后续可用于控制哪些用户能检索该资料。 | 它必须在检索前执行，不能只写在提示词里。 |
| `version` | 资料版本号。 | 防止回答引用旧制度。 | 新旧版本同时存在时，需要明确当前有效版本。 |
| 语义边界 | 一段内容能够独立表达完整业务含义的边界。 | 解释为什么优先按章节和段落切分。 | 固定字数切分可能破坏语义边界。 |
| 固定长度切分 | 按固定字符数或 token 数切分文档。 | 可作为没有标题结构时的备选方法。 | 它容易切断句子、步骤和制度条款。 |

## 2. 资料检索

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| 关键词检索 | 根据问题中是否出现资料里的词来匹配内容。 | 当前最小检索实现使用这种方法。 | 它不懂同义词和语义，只认识字面匹配。 |
| 查询词 | 从用户问题中提取出来、用于检索的词。 | 当前由 `extract_query_terms()` 提取。 | 查询词不一定覆盖用户真实意图，例如漏掉同义表达。 |
| 检索分数 | 当前规则下资料获得的关键词命中得分。 | 用于给资料排序。 | 分数不是概率，也不是准确率。 |
| 标题权重 | 关键词出现在标题中时赋予更高分值。 | 当前标题每次命中 4 分，正文命中 1 分。 | 权重是人为规则，不是模型计算出来的真理。 |
| 排序 | 按检索分数从高到低排列资料。 | 决定哪些资料优先进入提示词。 | 排序靠前不代表资料一定正确。 |
| `top_k` | 只选择排序最靠前的 K 条资料。 | 当前默认取前 3 名，减少无关内容和 token。 | K 太小会漏资料，K 太大会引入噪声。 |
| 召回 | 从资料库中找出可能相关的资料。 | RAG 的第一步。 | 召回不是最终回答，召回结果仍需筛选和复核。 |
| 误召回 | 检索到了分数较高但实际不相关的资料。 | 例如“门诊日报”误召回“门诊叫号大屏”。 | 共同词、词义过宽和缺少业务词典都会导致误召回。 |
| 语义检索 | 根据内容含义而不是字面文字进行检索。 | 后续可解决同义词和自然表达问题。 | 通常需要 Embedding 模型和向量索引，成本和评估更复杂。 |

## 3. 提示词组装

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| grounded prompt | 带外部资料、要求模型基于资料回答的提示词。 | 把检索结果转成模型可使用的输入。 | grounded 不等于绝对正确，资料错误时仍会出错。 |
| 上下文 | 当前请求中提供给模型的资料和问题。 | 检索结果被放入上下文。 | 上下文不是永久记忆，每次请求都需要重新提供。 |
| system 消息 | 给模型设定角色、规则和输出格式的前置消息。 | 限制模型只能依据资料回答。 | system 提示是软约束，不是权限系统或安全边界。 |
| user 消息 | 包含参考资料和当前问题的用户消息。 | 存放召回片段的标题、正文和问题。 | 资料需要带编号，方便回答引用和程序校验。 |
| 资料编号 | 例如 `KB-007`，表示资料片段来源。 | 模型回答通过编号说明依据。 | 有编号不代表编号一定有效，仍需程序校验。 |
| `insufficient` | 表示现有资料是否不足。 | 资料不足时应为 `true`，避免模型强行编造。 | 它不是回答长度不足，而是资料依据不足。 |
| `need_human_review` | 表示是否需要人工复核。 | 涉及患者安全或判断不确定时置为 `true`。 | 它不是权限审批字段，仍需接入真实业务流程。 |

## 4. 回答生成与校验

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| Grounded Answer | 基于召回资料生成的回答。 | 第 4 部分的目标输出。 | 它可能受到错误资料和模型判断偏差影响。 |
| `used_sources` | 模型回答实际声明的资料编号列表。 | 用于检查回答是否引用了真实召回资料。 | 不能仅凭它判断资料是否真正支持回答。 |
| JSON 校验 | 检查回答字段是否存在、类型和枚举是否合法。 | 保证程序能够稳定读取结果。 | 格式正确不代表业务结论正确。 |
| 引用校验 | 检查 `used_sources` 是否属于本次召回资料。 | 防止模型编造来源编号。 | 它不能检测引用内容是否相关。 |
| 业务复核 | 人工判断资料是否支持回答、结论是否完整。 | RAG 生产流程的最后保障。 | 不能只依赖程序校验或模型自我判断。 |
| `prompt_tokens` | 输入消息消耗的 token。 | 记录本次 RAG 请求的输入成本。 | 输入包含 system、资料和问题，不只是用户问题。 |
| `completion_tokens` | 模型生成阶段消耗的总 token。 | 记录回答和推理成本。 | 不只包含最终可见正文。 |
| `reasoning_tokens` | 生成阶段中用于内部推理的 token。 | 解释为什么有时正文很短但生成量较大。 | 不是所有模型或模式都会产生该字段。 |
| `visible_completion_tokens` | 本课按 completion 减 reasoning 计算出的可见输出及其他 token。 | 帮助观察可见输出占比。 | 它是课程计算值，不是官方独立字段。 |
| `total_tokens` | 本次请求的总 token。 | 公式为 `prompt_tokens + completion_tokens`。 | 本次为 519，仅代表这一条测试工单。 |
| `finish_reason` | 模型停止生成的原因。 | `stop` 表示正常结束，`length` 表示达到上限。 | 正常结束不代表业务回答正确。 |
| Prompt Cache | 对请求中相同前缀进行复用的缓存机制。 | 可降低重复提示词的成本。 | 缓存是否命中取决于前缀是否保持一致；本课本次命中为 0。 |

## 6. 本课最需要区分的概念

```text
参数记忆 ≠ 外部知识库
检索分数 ≠ 准确率
召回资料 ≠ 一定相关
JSON 正确 ≠ 业务回答正确
引用编号存在 ≠ 内容一定支持回答
程序校验 ≠ 人工业务复核
```
