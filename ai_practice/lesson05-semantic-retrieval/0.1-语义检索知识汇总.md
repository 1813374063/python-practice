## 专业名词汇总

### 1. 语义检索原理

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| 关键词检索 | 依据文字是否相同或包含来匹配资料。 | 作为语义检索的对照方法。 | 无法可靠识别同义表达。 |
| 语义检索 | 根据文本含义的接近程度检索资料。 | 本课核心方法。 | 不是照抄原词，而是比较向量。 |
| 语义鸿沟 | 用户表达方式和资料原文不同，但含义接近。 | 解释“检验结果打不开”和“检验报告查询失败”为什么应相关。 | 关键词不同不代表语义不同。 |
| 同义表达 | 文字不同但意思接近的说法。 | 语义检索重点解决的问题。 | 缩写、行业口语和专业术语都可能形成同义表达。 |

| 词义消歧 | 判断一个词在当前语境中的具体含义。 | 说明文字相同不代表一定相关。 | “门诊”在大屏和日报问题中含义范围不同。 |
| 语义向量 | 将一段文本编码成的数字列表。 | 语义检索比较的基本对象。 | 单个数字没有直观业务含义，应整体比较。 |

| Embedding | 把文本转换成语义向量的过程或结果。 | 语义检索的核心步骤。 | Embedding 不是关键词，也不是模型生成的回答。 |
| 向量维度 | 一个 Embedding 包含的数值个数。 | 决定向量存储和计算规模。 | 维度高不自动代表业务效果一定好。 |

| 相似度 | 两个向量靠近程度的数值。 | 用于给候选资料排序。 | 相似度高只表示模型认为含义接近，不代表内容真实。 |
| 余弦相似度 | 比较两个向量夹角的相似度指标。 | 常用来比较文本 Embedding。 | 它不是百分制准确率，解释要结合具体模型和阈值。 |
| 向量距离 | 两个向量在空间中的距离。 | 距离越小通常表示越接近。 | 距离和相似度的方向相反。 |
| 向量索引 | 用于快速查找相近向量的数据结构。 | 当资料规模变大时避免逐条暴力比较。 | 索引不是原始资料，资料原文仍需单独保存。 |
| 语义检索流程 | 资料向量化后入库，再把问题向量化并查找最接近资料。 | 连接文档准备、索引和回答生成。 | 资料和问题必须使用兼容的同一 Embedding 模型。 |

### 2. 检索方法比较

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| 精确匹配 | 文字完全相同才算匹配。 | 适合编号、代码和固定字段。 | 无法处理自然语言改述。 |
| 关键词检索 | 统计关键词命中并排序。 | 成本低、可解释，适合作为基线。 | 同义词和口语表达容易漏召回。 |
| 语义检索 | 比较文本向量的含义接近程度。 | 应对话术变化和同义表达。 | 可能忽略编号、缩写和精确规则。 |
| 混合检索 | 同时使用关键词和语义检索，再合并排序。 | 生产知识库通常采用的候选方案。 | 需要额外的融合、去重和评估。 |
| Top-K | 选择最接近的 K 条候选资料。 | 控制进入提示词的资料数量。 | K 越大不代表越好，会引入噪声和 token。 |
| 相关性阈值 | 只接收相似度达到最低要求的资料。 | 防止明显不相关的资料进入回答。 | 阈值必须用真实业务样例评估。 |
| 重排序 | 对初步召回的候选资料再次精细排序。 | 提高最相关资料进入提示词的概率。 | 会增加模型、延迟和成本。 |

### 3. Embedding 工程边界

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| Embedding API | 通过接口把文本转换为向量的服务。 | 使用语义检索时会调用。 | 会消耗 token，并涉及数据外发风险。 |
| Token 消耗 | Embedding 模型按输入文本量计费或计量。 | 影响资料首次入库和后续新增的成本。 | 资料更新后可能必须重新生成向量。 |
| 向量存储 | 保存资料编号和对应向量的位置。 | 支持检索时快速取回候选资料。 | 向量存储不应替代原文和权限系统。 |
| 模型一致性 | 资料和查询必须使用兼容的同一 Embedding 模型。 | 保证向量可比较。 | 更换模型后旧索引通常需要重建。 |
| 权限过滤 | 在检索前或检索中加入用户访问范围限制。 | 防止越权检索院内资料。 | 不能只在回答提示词里做权限控制。 |
| 脱敏 | 发送 Embedding 前移除不必要的敏感信息。 | 降低患者数据外发风险。 | 脱敏不能替代授权和访问审计。 |
| 重新索引 | 资料更新或模型变化后重新生成向量。 | 保持知识库最新且可比较。 | 只更新原文而不更新向量会导致检索旧内容。 |

### 4. 业务判断

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| 召回质量 | 正确资料是否进入候选列表。 | 决定语义检索的上限。 | 生成模型无法稳定修复没有召回的答案。 |
| 精确率 | 召回结果中真正相关资料的比例。 | 用于评估是否引入太多噪声。 | 精确率高不代表没有漏掉资料。 |
| 召回率 | 全部相关资料中被找出的比例。 | 用于评估是否漏掉关键资料。 | 召回率高可能伴随噪声增加。 |
| 业务基线 | 先用简单方法记录现有效果，再比较新方法。 | 关键词检索可作为语义检索的业务基线。 | 不能只看单个成功样例就宣布提升。 |
| 语义误召回 | 表面含义接近但业务上无关的资料被召回。 | 提醒语义检索不是绝对正确。 | 需要业务标签和人工复核。 |

### 5. 工程落地与选型

| 名词 | 一句话解释 | 在本课中的作用 | 容易混淆点 |
|---|---|---|---|
| Embedding 模型选型 | 根据语言、业务、成本、部署方式和效果选择向量模型。 | 语义检索的第一项工程决策。 | 模型榜单排名不能替代本医院业务测试。 |
| 中文能力 | 模型对中文分词、缩写、口语和专业表达的理解能力。 | 医院知识检索必须重点验证。 | 英文榜单效果好不代表中文场景一定好。 |
| 最大输入长度 | 单次 Embedding 能处理的最大文本长度。 | 决定切分片段是否会被截断。 | 超长文本可能被截断而没有明显报错。 |
| 向量维度 | 每个 Embedding 包含的数值数量。 | 影响存储空间、检索速度和成本。 | 更高维度不自动代表业务效果更好。 |
| 向量存储 | 保存资料编号、版本、权限与向量映射的系统。 | 支持相似度检索和候选资料回查。 | 向量存储不能代替原文、权限数据库和审计系统。 |
| 索引结构 | 组织向量以便快速近似查找的结构。 | 资料规模增长后降低检索延迟。 | 近似索引可能牺牲少量召回率换取速度。 |
| 增量索引 | 只对新增或更新的资料片段重新生成向量。 | 降低日常更新成本。 | 必须准确识别哪些片段发生变化。 |
| 重新索引 | 模型、切分规则或资料版本变化后重建向量。 | 保持资料与问题向量可比较。 | 只改原文不重建向量会返回旧内容。 |
| 权限过滤 | 检索前限制用户可访问的资料范围。 | 防止越权检索内部制度。 | 不能只靠回答提示词隐藏无权内容。 |
| 数据最小化 | 只发送完成 Embedding 所需的最少文本。 | 降低外发敏感数据的范围。 | 去掉姓名仍可能通过其他字段重新识别个人。 |
| 向量缓存 | 对未变化文本复用已有向量。 | 减少重复 Embedding 调用。 | 缓存必须绑定模型版本和文本内容。 |
| 混合检索 | 合并关键词与语义检索的候选结果。 | 兼顾同义表达和精确编号。 | 需要去重、融合排序和统一评估。 |
| 结果融合 | 把不同检索方法得到的候选合并并排序。 | 避免完全丢失精确命中结果。 | 简单拼接容易让噪声或偏置放大。 |
| 重排序 | 对初步候选进行第二轮更精细排序。 | 提高正确资料进入 Top-K 的概率。 | 会增加延迟、模型调用和成本。 |
| 审计日志 | 记录谁在什么时间检索和查看了哪些资料。 | 满足安全追溯和故障排查。 | 日志本身也可能包含敏感信息，需要保护。 |
| 私有化部署 | 在院内环境运行 Embedding 和后端服务。 | 降低内部资料外发风险。 | 仍然需要权限、密钥、更新和容量管理。 |

### 6. 场景选型判断

| 场景特征 | 优先方案 | 原因 |
|---|---|---|
| 资料很少，用户使用固定术语 | 关键词检索 | 成本低、可解释、足以满足需求 |
| 用户说法变化多，同义表达频繁 | 语义检索 | 更适合识别含义接近 |
| 同时包含自然语言和精确编号 | 混合检索 | 保留编号精确匹配，同时补充语义召回 |
| 资料更新频率高 | 增量索引与重新索引机制 | 防止回答引用旧制度 |
| 涉及患者隐私或内部敏感资料 | 权限过滤、脱敏、私有化或授权接口 | 数据合规优先于效果 |
| 无法建立业务测试集 | 暂缓纯语义检索上线 | 无法判断效果和风险 |
