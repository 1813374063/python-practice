## 专业名词汇总

### 1. Python 基础

| 名词 | 一句话解释 | 容易混淆点 |
|---|---|---|
| 变量 | 给一个值起名字，后续通过名字使用它。 | 变量保存值，不等于值本身。 |
| 数据类型 | 数据属于字符串、整数、浮点数、布尔值等类型。 | `"32"` 是字符串，`32` 是整数。 |
| 列表 | 按顺序保存多个元素的数据结构。 | 列表用 `[]`，元素有位置索引。 |
| 字典 | 用键值对保存数据。 | 按键取值的写法是 `data["键"]`。 |
| 条件判断 | 根据条件决定执行哪段代码。 | `if` 判断条件，不负责遍历。 |
| 循环 | 重复执行一组代码。 | `for` 适合遍历，`while` 适合按条件重复。 |
| 函数 | 把可复用逻辑封装起来并接收输入、返回结果。 | 定义函数不会执行，调用函数才执行。 |
| 参数 | 调用函数时传入函数的数据。 | 参数和返回值不是同一个概念。 |
| 返回值 | 函数处理完成后交还给调用位置的数据。 | 没有 `return` 时默认返回 `None`。 |
| 异常 | 程序运行中出现的错误状态。 | `try/except` 用于处理可预期错误。 |
| 文件读写 | 从文件读取或向文件写入数据。 | 写文件通常需要指定 `encoding="utf-8"`。 |
| CSV | 用逗号分隔字段的文本数据格式。 | 读取后每行仍是字符串，需要必要转换。 |
| 脏数据 | 缺失、格式错误或无法直接计算的数据。 | 脏数据应记录并跳过，不能伪装成有效值。 |
| SQLite | Python 可直接使用的轻量数据库。 | 数据库文件保存数据，游标负责执行 SQL。 |
| SQL | 用于查询和修改关系数据库的语言。 | CRUD 分别表示增、查、改、删。 |
| 游标 cursor | 执行 SQL 和获取结果的数据库操作句柄。 | 执行增删改后需要 `commit()`。 |

### 2. Git 与 GitHub

| 名词 | 一句话解释 | 容易混淆点 |
|---|---|---|
| 仓库 repository | 保存项目文件和版本记录的目录。 | 本地仓库和 GitHub 远程仓库不是同一个位置。 |
| 工作区 | 当前正在编辑和查看文件的位置。 | 修改工作区文件后，Git 不会自动提交。 |
| 暂存区 | 准备放入下一次提交的文件变化。 | `git add` 是放入暂存区，不是上传 GitHub。 |
| commit | 一次带说明的版本快照。 | commit 先在本地产生，不等于 push。 |
| remote | 本地仓库记录的远程仓库地址。 | `origin` 只是远程仓库的常用别名。 |
| push | 把本地提交发送到远程仓库。 | push 前通常先有 commit。 |
| pull | 把远程更新拉取并合并到本地。 | pull 不是上传命令。 |
| branch | 独立的开发分支。 | 常见默认分支名为 `main`。 |
| `.gitignore` | 指定哪些文件不进入 Git 跟踪。 | 已被跟踪的文件不能仅靠新增忽略规则自动移除。 |
| 合并冲突 | 两边修改同一位置时 Git 无法自动合并。 | 冲突需要人工确认保留内容。 |
