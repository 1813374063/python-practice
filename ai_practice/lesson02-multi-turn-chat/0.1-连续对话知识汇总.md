## 专业名词汇总

### 1. 连续对话

| 名词 | 一句话解释 | 容易混淆点 |
|---|---|---|
| 多轮对话 | 在多轮请求中持续使用此前用户和模型消息。 | 模型本身不会自动记住上一轮。 |
| 无状态 API | 服务端不保存每次请求的对话上下文。 | 无状态不等于不能连续对话，历史需要客户端发送。 |
| 对话历史 | 程序保存的 system、user 和 assistant 消息列表。 | 历史列表关闭程序后通常会消失。 |
| 上下文 | 本次请求中模型实际看到的消息。 | 只有进入本次 `messages` 的内容才属于当前上下文。 |
| `history` | 当前程序中保存对话历史的变量名。 | 它只是本地变量名，不是 API 固定参数名。 |
| `messages` | 接口规定的消息列表参数名。 | 不能写成 `history=history`。 |
| `append` | 把一条新消息追加到历史列表末尾。 | 忘记追加模型回答会导致下一轮失忆。 |
| 系统消息 | 设置角色、语气和回答规则的前置消息。 | 系统消息不会永久保存到模型参数。 |
| 用户消息 | 保存用户本轮输入。 | 不能把模型回答也放进用户角色。 |
| 模型消息 | 保存模型本轮回答。 | 模型回答需要程序主动追加回历史。 |
| 上下文窗口 | 模型一次请求最多能处理的内容范围。 | 历史无限增长最终会超过窗口。 |
| 程序记忆 | 由程序维护的对话历史。 | 它与模型参数记忆不是一回事。 |
| 退出条件 | 用户输入特定内容时结束循环。 | 循环需要明确退出方式。 |
