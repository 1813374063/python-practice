# ai_practice 学习文件规则

1. 基础阶段使用 `phaseNN-topic`，每门基础内容单独建文件夹。
2. 大模型课程使用 `lessonNN-topic`，每一课一个独立文件夹。
3. 课程脚本、数据、测试结果、笔记和知识卡片统一放在对应课程文件夹中。
4. `key.txt` 保留在 `ai_practice` 根目录，作为所有课程共享的本地密钥。
5. 不在 `ai_practice` 根目录继续堆放新课文件。
6. 本课文件直接放在课程文件夹根目录，不额外建立子目录。
7. 文件名统一使用 `x.x-原文件名.扩展名`。
8. 第一个 `x` 表示学习部分的编号，第二个 `x` 表示该部分内文件的生成顺序。
9. 每生成一个新文件，必须先说明它的用途、输入、输出、是否调用模型和运行方式。
10. 每课维护一个文件导航，记录已有文件的阅读顺序和用途。
11. 一部分原则上只生成一个主要代码文件，通过参数控制可选行为，避免堆叠重复脚本。
12. 代码文件和运行结果要区分：代码用于执行，JSON、数据库和图片属于结果或资料。
13. 代码阅读只要求掌握入口、输入、输出和核心函数，不要求逐行理解全部语法。
14. 每部分先讲业务概念，再讲代码如何实现。
15. 自测题默认只考查概念、输入、输出和业务判断，不考具体语法。
16. 代码理解分成三级：知道用途、会运行看结果、需要修改时再读实现。
17. 除非明确进入代码阅读专项，否则代码实现细节不作为通过条件。
18. 每个一级目录维护一个独立的 Markdown 知识汇总文件，文件名可自定义。
19. 知识汇总文件使用 `x.x-自定义名称.md`，同时承担文件清单、阅读顺序和专业名词汇总。
20. 专业名词按该课学习部分分组，只汇总本课实际出现的名词。
21. 每个名词至少说明一句话定义、在本课中的作用和容易混淆点。
22. 不再为每课单独生成专业名词词卡文件。
23. 每个一级课程目录都必须拥有自己的知识汇总文件，名称体现在本目录课程内容。
24. 文件清单和专业名词只能来源于当前一级目录，不得跨目录汇总。
25. 后续课程新增名词时，只更新对应课程自己的知识汇总文件。

新文件说明模板：

```text
文件名称：
学习部分：
主要用途：
输入：
输出：
是否调用模型：
运行方式：
建议阅读顺序：
```

代码理解等级：

```text
A 必须理解：业务作用、输入和输出
B 黑盒使用：会运行、会查看结果，不必读实现
C 可选深入：需要修改代码时再阅读函数实现
```
