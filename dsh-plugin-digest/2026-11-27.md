## 0. 结论先说

1. **三个站点里只有一个真正"每日可抓"**：`star-history/top-committers` 是**人的榜**（服务端渲染，可抓），`trendshift` 的周/月榜是**前端渲染**，HTML 里没有条目，官方 API 需要付费 token。所以"每日检索这三个站"不能直接产出插件列表，必须补一条机器可读的管道。
2. **今天真正能落地的是 6 个原生 DSH 插件 + 3 个技能**（下文第 3、4 节），全部有作者、场景、装法、风险。
3. **你的装上正卡着一个真实故障**：`dsh-synapse` 今天 07:14 与 07:15 连续两次 `MUTATION_FAILED`（`.dsh-market/log.ndjson`）。这恰好是第 3 节 #1/#2 两个"体检类"插件的用武之地。
4. 生态现状：绝大多数插件是**单人、2–12 周龄、版本钉死在 0.2.x**，星数通胀严重（有 7 个月 47.9 万星的仓库）。判断标准应该是**下载量 + 测试 + npm provenance**，不是星数。

### 1.2 trendshift：为什么抓不到，以及替代方案

- 页面 HTTP 200，但正文只有导航和页脚 —— 列表在客户端渲染。
- 官方 API（`api.trendshift.io`，OpenAPI 3.1，v0.3.2）**全部端点都要 `Authorization: Bearer ts_live_…`**，属于 Trendshift Signal 订阅；限速 100 请求/分钟。端点长这样：
  - `GET /v1/trending/weekly`、`/v1/trending/monthly`
  - `GET /v1/trending/weekly/{year}/{week}`、`/v1/trending/monthly/{year}/{month}`
  - `GET /v1/github-trending/{date}`（GitHub 官方榜单的历史快照）
- **替代口径**（本期实际采用）：GitHub Search 按 `created` + `stars` 排序，等价于"新晋热门仓库"——
  - 本周：`created:>2026-11-20 stars:>50` → 1,337 个结果
  - 本月：`created:>2026-10-28 stars:>800` → 198 个结果
- 遗留问题：这个口径偏向**新仓库**，抓不到"老仓库突然涨星"。若要补，需要 Trendshift token 或第三方 trending 镜像。

1. **装插件 = 用你的权限跑第三方代码**。工具审批不沙箱插件进程；它能读文件、拿凭据、出网。

## 附录：`dsh-synapse` 安装失败复盘（16:10 已修复）

**现象**：今天 07:14、07:15 两次 `MUTATION_FAILED`；市场提示"允许构建脚本并重试"和"钉死 commit 或换回 npmjs.org 源"，两条都是**误导**。

**真实报错**（复现后拿到的完整输出）：

```
[ERR_PNPM_PREPARE_PACKAGE] Failed to prepare git-hosted package fetched from
"https://codeload.github.com/liangmianya/dsh-synapse/tar.gz/1c740dd…":
dsh-synapse@0.5.11 pnpm-install: `pnpm install`
Exit status 1
→ 'pnpm' 不是内部或外部命令，也不是可运行的程序
```

**根因**：git 包的 `prepare` 脚本里跑 `pnpm install && pnpm run build`，但 DSH 自带的 pnpm 是 `…\dependencies\pnpm\bin\pnpm.mjs`（由 node 调起），**从来没有作为 `pnpm` 命令暴露到 PATH**，于是子进程找不到它。构建脚本审批、commit 钉死、换源都治不了这个。

**修复**：在已在 PATH 上的 npm 全局目录放一个转发脚本，指向 DSH 自带的 node + pnpm：

`C:\Users\15634\AppData\Roaming\npm\pnpm.cmd`

```bat
@echo off
"C:\Users\15634\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe" "C:\Users\15634\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\pnpm\bin\pnpm.mjs" %*
```

**结果**：`dsh-synapse@0.5.11` 装成功，`pnpm run build`（5 个 `node --check`）通过，profile 的 `dependencies` + `bundles` 都已登记，健康检查 0 问题。

**维护提示**：DSH 升级后若 `dsh-runtimes` 下的 runtime 目录名变了，这个转发脚本要同步改路径；否则所有带 `prepare` 的 git 型插件会再次失败。

**顺带装上**：`dsh-plugin-ops-bundle@0.21.3`、`dsh-plugin-health@3.3.0`，两者工具已在本会话可用（`dsh_ops_sandbox_*`、`plugin_health`）。
