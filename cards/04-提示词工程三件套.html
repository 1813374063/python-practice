提示词工程三件套

角色设定 · 结构化输出 · Few-shot 少样本示例

1本课目标

  • 学会把“你是专家”升级为可执行的角色说明书。
  • 让模型通过 JSON Output 返回程序能读取的结构化数据。
  • 用少量标准示例引导模型稳定分类和输出格式。
  • 理解提示词是软约束，必须配合程序校验和人工复核。

2三件套总览

技术解决的问题核心限制
角色设定控制身份、任务、对象、步骤、约束和格式不能当作权限控制或安全边界
结构化输出让程序能稳定读取字段只保证 JSON 语法，不保证业务字段正确
Few-shot用示例说明分类边界和期望模式不修改模型参数，错误示例会带偏输出

3角色设定

有效角色提示词不是一句身份声明，而是一份工作说明书。

你是一名【角色】，负责【职责】。

任务目标：
【要解决的具体问题】

事实规则：
1. 只能把用户明确提供的信息列为事实。
2. 其他内容必须标记为推测或待核实。
3. 不得编造院内制度、日志、患者数据或处理结果。

输出约束：
1. 按指定顺序组织内容。
2. 只输出指定格式。
3. 最多输出 3 项行动。

医疗合规：
不得输出真实患者姓名、证件号、病历号、手机号等敏感信息。
实测差异：弱角色只写“你是一名医院信息科工程师”，模型输出了长篇通用排障手册；强角色明确事实、动作、证据、升级条件和表格格式后，模型输出了可直接执行的 3 行动作表。
关键认知：角色提示词只能影响模型输出，不是权限控制，也不是数据保护机制。真正的保护必须在程序层做权限校验、脱敏、访问控制与审计。

4结构化输出

4.1 三层链路

提示词要求字段结构
→ API 开启 JSON Output
→ Python 执行 json.loads 和字段校验
response = client.chat.completions.create(
    model=MODEL,
    messages=messages,
    response_format={"type": "json_object"},
    max_tokens=4000,
)

content = response.choices[0].message.content
data = json.loads(content)

4.3 真实报错：内容为何为空

第一次设置 max_tokens=1200 时，模型返回空字符串。响应统计显示： finish_reason="length"，completion_tokens=1200， reasoning_tokens=1200。推理 token 已耗尽上限，没有剩余空间输出可见 JSON。

修复：把 max_tokens 提高到 4000，并按官方要求加入 JSON 格式示例。DeepSeek 文档还提示 JSON Output 可能偶发返回空内容，因此程序采用最多 3 次重试。

4.4 程序必须继续校验

required_keys = {"issue", "confirmed_facts", "unconfirmed", "actions"}
missing_keys = required_keys - data.keys()

if missing_keys:
    raise ValueError(f"JSON 缺少必要字段：{sorted(missing_keys)}")

data.keys() 是字典键视图，支持集合运算。集合减法返回“要求字段中实际缺失的部分”。

4.5 异常处理

try:
    data = json.loads(content)
except json.JSONDecodeError as exc:
    raise ValueError(f"模型没有返回合法 JSON：{exc}") from exc
  • try：尝试解析 JSON。
  • except：捕获 JSON 格式错误。
  • raise ValueError：抛出更清楚的中文错误。
  • from exc：保留原始异常，作为新异常的直接原因。

5Few-shot 少样本示例

方式是否提供示例
Zero-shot0 个
One-shot1 个
Few-shot通常 2 到 5 个
messages = [
    {"role": "system", "content": "分类规则和 JSON 格式"},
    {"role": "user", "content": "示例工单 1"},
    {"role": "assistant", "content": "标准结果 1"},
    {"role": "user", "content": "示例工单 2"},
    {"role": "assistant", "content": "标准结果 2"},
    {"role": "user", "content": "真正需要分类的新工单"},
]

user 和 assistant 为什么成对：user 提供输入，assistant 提供期望模型模仿的标准输出。成对组合形成完整的“输入 → 输出”示范。

实测：药房窗口打印机无法打印处方，其他业务正常。模型分类为“终端与外设”，优先级 P1，并要求人工复核，因为处方打印可能影响发药与患者用药。

风险：错误或矛盾示例会带偏分类；示例过长会增加 token、费用和延迟；过时示例可能违背最新流程；示例可能包含患者或院内敏感信息；覆盖不足时模型可能强行套用错误类别。

6temperature 温度参数

取值倾向输出特点常见任务
0 到 0.3更集中、变化更少分类、抽取、JSON
0.7 到 1.0较平衡问答、总结
1.2 到 2.0更发散、更有变化创意与多方案
DeepSeek 当前官方文档显示：temperature 范围为 0 到 2，默认 1；但在 thinking mode 下没有效果。低温度也不等于每次绝对相同，它只是影响采样倾向或表达“低随机性”的意图。
