学习卡片 03
大模型对话基础
模型没有记忆 · 三种角色 · 请求与响应的结构

1本环节目标

能写出一个连续对话的脚本，并说清"模型为什么能接上话"。

一句话原理：模型本身没有记忆，每一次请求都是独立的；"它记得上一句"是我们把全部历史一起发过去的功劳。

2核心概念

2.1 模型是"无状态"的

  • 每次调用 create() 都是全新的一次请求，模型看不到你上一次问了什么
  • 所谓"连续对话"，是程序把全部历史打包发过去实现的
  • 因此历史越长，请求越大、消耗越多 → 真实产品会做"历史管理"（截断、摘要）

2.2 三种角色（role）

角色谁在说话作用
system幕后导演给模型定身份、语气和规矩；用户看不到它
user用户提出问题
assistant模型它之前的回答（必须由程序存回历史）

2.3 对话历史就是一个"列表装字典"

history = [
    {"role": "system",    "content": "你是一位医院信息科的资深工程师……"},
    {"role": "user",      "content": "什么是RAG？"},
    {"role": "assistant", "content": "RAG就是先查资料再回答……"},
    {"role": "user",      "content": "它和微调有什么区别？"},
]

这和第1阶段学的 records = [{"科室": "内科", ...}, ...] 是同一种结构——列表装字典。只是这次装的不是业务记录，而是对话记录。

2.4 响应是个对象，用点号逐层取值

response.choices[0].message.content
打印里看到的代码里对应
ChatCompletion(...)response
choices=[Choice(...)]response.choices（列表）
Choice(index=0, ...)response.choices[0]
message=ChatCompletionMessage(...)response.choices[0].message
content='...'response.choices[0].message.content（正文）

2.5 几个值得记住的字段

字段含义用途
id本次请求的唯一编号找平台排查问题时报它，定位最快
finish_reasonstop=正常说完，length=被长度截断排查"回答不完整"
choices候选答案列表我们只取第 0 个
logprobs词概率，默认 None可选功能，暂不使用

3操作流程

from openai import OpenAI

BASE_URL = "https://api.deepseek.com"
MODEL = "deepseek-flash"

with open("key.txt", encoding="utf-8") as f:
    api_key = f.read().strip()

client = OpenAI(api_key=api_key, base_url=BASE_URL)

history = [
    {"role": "system", "content": "你是一位医院信息科的资深工程师，回答专业、简洁，每次不超过100字。"}
]

print("开始对话吧，输入 exit 退出。\n")

while True:
    question = input("我：")
    if question == "exit":
        break

    history.append({"role": "user", "content": question})                       # 1 收下用户的话

    response = client.chat.completions.create(model=MODEL, messages=history)    # 2 全量发送
    answer = response.choices[0].message.content

    history.append({"role": "assistant", "content": answer})                    # 3 存回模型的话

    print("AI：" + answer + "\n")

三个要点

  1. history 初始化在循环之外——写在循环里会每轮清空，模型立刻失忆
  2. 发送的是整个 history，不是这一句话——这就是"打包"的含义
  3. 模型的回答必须 append 回历史（第 3 步），否则下一轮它不知道自己说过什么

运行方式：cd ai_practice 然后 python chat.py。因为有 input() 要等你打字，必须在终端里运行。

4常见报错与排查

报错 / 现象原因解决
TypeError: Missing required arguments; Expected either ('messages' and 'model') or ...参数名写错（例如写成 history=history）参数名按接口规定写：model=、messages=，左边不能改
400 invalid_request_error（模型名不支持）模型名写错，或平台不支持用服务端返回的支持列表／官方文档里的名字，注意大小写
401 AuthenticationErrorkey 错误、失效或没读到检查 key.txt；确认它被 .gitignore 忽略
AI 答非所问、像"失忆"忘了把模型回答 append 回历史检查第 3 步那行代码
回答满屏 \n、挤成一坨打印的是对象，不是字符串打印 response.choices[0].message.content
finish_reason='length'回答被长度限制截断放宽长度限制，或要求模型更简洁
排查心法：看不懂的返回值，先 print(type(x)) 和 print(x) 看一眼结构；调试代码用完即删，别留在正式脚本里。

5自查清单

  • 能不看代码说清"AI 为什么能接上话"
  • 能说出 system / user / assistant 三种角色的区别
  • 能逐层解释 response.choices[0].message.content 的取值过程
  • 能说明 finish_reason 为 stop 和 length 的差别
  • 能独立写出带 system 设定的多轮对话脚本
  • 看到"缺少必填参数"的报错，第一反应是检查参数名拼写
  • 知道 history 必须初始化在循环之外

6本课实测记录

实验观察到的结果
把 system 改成"医院信息科工程师 + 科普作者、多用比喻"同一个模型、同一个问题，输出风格明显变化（用"超级实习生""旋钮"打比方）——提示词确实能控制输出
把"模型回答 append 回历史"注释掉AI 开始答非所问——证明模型本身无记忆
